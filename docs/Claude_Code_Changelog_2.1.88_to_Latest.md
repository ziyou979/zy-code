## 🔒 v2.1.88 — 源码泄露版本 (2026-03-31)

### 事件背景
2026 年 3 月 31 日，Claude Code v2.1.88 的 npm 包因为打包错误，将完整的 `.map` 源映射文件包含在内，导致 1906 个 TypeScript 源文件、51.2 万行代码被完全曝光 [3][4]。这不是 Anthropic 第一次发生类似事件，但此次泄露规模空前。

### 技术细节
- **泄露原因**: npm 包中遗留了一个 59.8MB 的 `cli.js.map` 文件
- **泄露内容**: 核心架构、工具系统实现、安全机制等完整源码
- **影响范围**: 涉及权限检查、MCP 协议实现、Hooks 系统等核心模块

### 后续响应
Anthropic 在事件发生后迅速采取行动，在 10 天内连续发布 10 个版本进行修复和加固 [3]。

## 🛠️ v2.1.89 — 大规模问题修复 (2026-04-01 01:07 UTC)

### 新增功能
- **无头会话暂停恢复**: 向"PreToolUse"挂钩添加了"defer"权限决策，无头会话可以在工具调用时暂停并使用 `-p --resume` 恢复以使挂钩重新评估
- **无闪烁屏幕渲染**: 添加 `CLAUDE_CODE_NO_FLICKER=1` 环境变量，选择具有虚拟回滚功能的无闪烁替代屏幕渲染
- **自动模式分类器重试**: 添加"PermissionDenied"钩子，该钩子在自动模式分类器拒绝后触发，返回 `{retry: true}` 可告诉模型重试
- **子代理提及建议**: 将命名子代理添加到"@"提及提前输入建议

### 重要修复（42 项）
- **符号链接安全检查**: 修复 `Edit(//path/**)` 和 `Read(//path/**)` 允许规则检查解析的符号链接目标，而不仅仅是请求的路径
- **Windows CRLF 处理**: 修复 Windows 上的编辑/写入工具加倍 CRLF 并剥离 Markdown 硬换行符（两个尾随空格）
- **内存泄漏修复**: 大型 JSON 输入在长时间运行的会话中保留为 LRU 缓存键的问题
- **大文件崩溃修复**: 从非常大的会话文件（超过 50MB）中删除消息时发生的崩溃
- **LSP 服务器僵尸状态**: 崩溃后 LSP 服务器僵尸状态修复，服务器现在在下一个请求时重新启动
- **多语言文本截断**: 包含 CJK 或表情符号的提示历史条目在落在 4KB 边界上时被静默删除的问题
- **语音模式修复**: macOS Apple Silicon 上麦克风权限请求问题
- **深层链接修复**: `claude-cli://` 深层链接在 macOS 上无法打开的问题

### 体验优化
- 改进折叠工具摘要显示 `ls`/`tree`/`du` 的"列出的 N 个目录"而非"读取 N 个文件"
- Bash 工具在格式化程序/linter 命令修改已读取文件时发出警告
- PowerShell 工具提示提供适合版本的语法指导（5.1 vs 7+）
- 思维摘要默认不再生成（可在 settings.json 设置 `showThinkingSummaries: true` 恢复）

### 预告功能
- `/buddy` 命令将于 4 月 1 日上线——孵化一个小生物观察用户编码 [1]

- **终端删除异常**: 修复"cmd+delete"在 iTerm2、kitty、WezTerm、Ghostty 和 Windows 终端上不删除到行首的问题

- **Windows 版本清理**: 修复 Windows 版本清理不保护活动版本的回滚副本的问题

### 性能优化

## ⚙️ v2.1.105 — 稳定性与插件能力增强 (2026-04-13 21:53 UTC)

### 新增功能
- **EnterWorktree path 参数**: 允许工具直接切换到当前仓库的某个已有 worktree，更方便管理多分支开发，避免手动 git worktree list 再切换，对多环境、多版本调试非常有用
- **PreCompact hook 阻止压缩**: hook 可以通过退出码 2 或返回 `{"decision":"block"}` 来阻止 compaction（压缩），插件或系统可以在不安全、不合适的时机阻止压缩，对数据一致性、调试、插件控制非常关键
- **插件后台监控（monitors）**: manifest 顶层新增 monitors，在 session 启动或 skill 调用时自动启动，插件可以持续监听事件、状态变化，类似守护进程（daemon），适合日志监控、资源监控、自动修复等场景

### 命令统一
- **/proactive 成为 /loop 的别名**: 统一命令体系，减少用户困惑

### 流式 API 改进
- **5 分钟无数据自动中止**: 改进流式 API，5 分钟无数据自动中止并回退到非流式，避免"无限等待"，提升稳定性，对网络不稳定环境非常友好

- **网络错误提示改进**: 连接错误时立即显示"正在重试"，不再出现"静默转圈"，用户体验显著提升

- **/doctor 布局改进**: 更清晰的状态图标，新增 f 快捷键自动修复问题，对开发者非常友好

## 🏆 v2.1.143 — 插件依赖管理与背景会话增强 (2026-05-15)

**发布日期**: 2026 年 5 月 15 日

**核心新特性**:

- **PowerShell 执行策略**: PowerShell 工具现在传递 `-ExecutionPolicy Bypass`，可通过 `CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1` 选择退出
- **后台会话模型保持**: 后台会话从空闲唤醒后，现在会保留你设置的模型和 effort level
- **附加会话切换**: 附加 agent 会话中 Shift+Tab 现在包含 auto mode 循环

**关键 Bug 修复**:
- **凭证文件损坏**: 修复损坏的 `.credentials.json`（含非数组 `scopes` 值）导致 CLI 启动挂起或 OAuth 令牌刷新静默中止的问题
- **右键粘贴修复**: 修复 Windows Terminal 和 WSL 中 `claude agents` 的右键粘贴问题
- **停止钩子死循环**: 修复重复阻止的停止钩子无限循环——现在在连续 8 次阻止后会结束轮次并显示警告（可通过 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` 覆盖）
- **/loop 唤醒取消**: 修复 Esc/Ctrl+C 无法取消待处理的 `/loop` 唤醒的问题
- **/goal 评估器触发**: 修复 `/goal` 评估器在后台 shell 或委托的子代理仍在运行时触发的问题
- **NO_COLOR/FORCE_COLOR**: 修复 settings.json 的 `env` 中这些变量剥离 Claude Code 自身 UI 颜色的问题——现在仅应用于子进程
- **Agent View PowerShell 风暴**: 修复 agent view 在 Windows 上列出会话时生成重复 PowerShell 进程的问题
- **/bg 无提示发送**: 修复 `/bg` 无提示时发送"continue"到 fork 会话的问题——现在 fork 会等待输入
- **--agent 插件代理查找**: 修复 `--agent <name>` 找不到插件贡献的代理（缺少 `plugin:` 前缀）的问题
- **删除会话转录**: 修复从 agent view 删除会话时未移除其转录文件的问题
- **后台作业权限错误**: 修复 macOS 上后台作业会话读取 `~/Documents`、`~/Desktop`、`~/Downloads` 时的"Operation not permitted"错误（即使有完全磁盘访问权限）
- **/bg 配置保持**: `/bg` 现在保留 `--mcp-config`、`--settings`、`--add-dir`、`--plugin-dir` 和 `--strict-mcp-config`
- **后台作业默认权限模式**: 从 `claude agents` 启动的后台会话现在遵守 settings.json 中的 `permissions.defaultMode`
- **fallback-model 保持**: `/bg` 和 `←`-detach 现在保留 `--fallback-model`
- **allow-dangerously-skip-permissions 保持**: `/bg` 和 `←`-detach 现在保留 `--allow-dangerously-skip-permissions`
- **守护进程生成回退**: 修复后台守护进程生成在 `~/.local/bin/claude` 启动器缺失或不可执行时回退到运行中的二进制文件
- **默认绕过模式修复**: 修复 `claude agents --allow-dangerously-skip-permissions` 将分发的会话默认设为绕过模式而非在权限循环中可用 [6]

## 🆕 v2.1.139 重大更新详解 (2026-05-12)

### 一、Agent View：多会话统一调度界面

过去开发者在并行运行多个 Agent 时，需要自己维护大量 Terminal 窗口或依赖 tmux 等工具手动管理任务状态。Agent View 在 CLI 之上新增了一层"Agent 调度视图" [2]：

**核心能力**:
- **状态可视化**: 每一行对应一个独立 Agent 会话，展示当前状态、最近回复内容、最近交互时间
- **智能标记**: "等待输入"状态直接标识需要用户确认的 Agent，运行中的 Agent 持续显示执行状态
- **内联回复**: 无需切换 Terminal 即可直接回复问题并继续推进流程
- **Peek 机制**: 无需真正进入某个会话，就能快速查看最近一轮对话内容

**访问方式**:
- 命令行：`claude agents`
- 快捷键：在会话中按左方向键

**用户反馈**:
- 正面：开发者表示"等待已久"，解决了同时跑五六个工作流时频繁切换标签页的精力消耗问题 [2]
- 期待：希望后续能直接显示每个 Session 最近修改的文件或 commit，方便中断后快速恢复上下文
- 谨慎：有开发者认为相比多个并行的 Agent，一个能持续交付结果的单 Agent 实际价值可能更高 [2]

### 二、/goal 命令：目标驱动自主执行

**功能特点**:
- 设定目标后 Claude 跨轮次自主推进，无需每轮都重新描述需求
- 实时显示耗时、轮数和 Token 消耗统计
- 适合需要多轮迭代的复杂任务（如重构模块、添加完整功能）

### 三、后台运行增强

**新增命令**:
- `/bg`：将当前会话放到后台运行
- `claude --bg [task]`：直接启动后台任务

**适用场景**:
- PR 检查
- 代码仓库扫描
- Dashboard 更新
- 其他长时间运行的任务

**优势**:
- 不占用当前终端窗口
- 任务可像后台服务一样持续执行
- 在 Agent View 中可直接查看哪些任务卡住、哪些等待确认

### 四、技术意义与行业影响

Agent View 的出现标志着 AI 编程工具开始解决"Agent 太多"之后的新问题：

1. **人类成为瓶颈**: 当 Agent 能够长时间运行、并行处理任务后，频繁切换 Terminal、反复恢复上下文、确认任务状态等工作反而让人类成为工作流瓶颈 [2]

2. **关系转变**: 开发者与 Agent 的关系像是在监督一条持续运行的 Agent 流水线，而非传统的"一对一"协作模式 [2]

3. **工具进化**: 从单 Agent 工具进化为可同时调度多个 Agent 的工作台，Claude Code 正在成为开发者的"AI 指挥中心"
- 性能与稳定性持续优化
- 新增功能和命令
