# 提交延迟与长会话性能对照（2026-09-09）

## 本轮修复和测量

输入提交会清空输入框、设置处理中状态，然后等待前置 hooks、构建附件、更新消息并启动模型请求。长会话更新消息时，原 normalizeMessages 为所有 assistant/user 内容块重新创建渲染对象。MessageRow 的比较器首先比较消息引用，因此历史行会失去静态复用机会。

新增按不可变消息引用缓存的 createMessageNormalizer，仅供 Messages 渲染路径使用，通用 normalizeMessages 和 API 路径语义不变。WeakMap 不强持有已移除消息；按多块消息导致的 UUID 派生上下文分别缓存。追加保留历史行引用，内容替换和前缀插入/删除仍正确更新。缓存是每个消息视图实例所有，不是全局强引用历史表。

复现命令：`bun scripts/bench-message-normalization.ts`。3000 条双块消息，30 次末尾更新，本机一次结果：

| 路径 | 中位耗时 | P95 | 复用历史渲染对象 |
| --- | ---: | ---: | ---: |
| 全量规范化 | 1.674 ms | 3.338 ms | 0 / 6000 |
| 引用缓存 | 0.165 ms | 0.437 ms | 6000 / 6000 |

这是消息转换微基准，不含 React 布局、终端写入或模型请求；不能据此声称回车端到端延迟降低相同比例。缓存首次填充仍需处理全部消息。

第二处修复是 @ 文件大小检查：将唯一调用路径中的同步 stat 改成 await 异步 stat。慢文件系统不再在检查大小时阻塞 JS 事件循环；大小上限、缺失文件与后续读取处理保持一致。

第三处补充是查询计时：REPL 正常提交从等待 pending hooks 之前启动计时，并让 handlePromptSubmit 保留这段检查点；排队输入不会重置正在运行的查询计时。便于区分 hooks、附件、请求发送和首块等待。此前计时从 pending hooks 完成之后才开始，可能漏掉用户感知的等待。这不是 hooks 加速，也没有跳过 hooks。

## CC 对照与检查覆盖

主来源：https://platform.claude.com/docs/en/release-notes/claude-code 。本机 2.1.263 二进制也检查了附件收集阶段：用户输入附件先并行收集，之后才进行依赖这些触发信息的阶段。zycode 同样存在依赖，不能为了减少等待而直接把所有阶段并行。

| 检查路径 | 结果及处理 |
| --- | --- |
| 回车提交与历史行重建 | 本轮新增引用缓存，避免历史对象全量失效 |
| @ 文件检查 | 对齐 CC 发布记录中减少事件循环停顿的方向，改为异步 stat |
| 提交前 hooks | 保留等待语义；补齐计时，暂未取得用户实际 hooks 延迟数据 |
| onSubmit 的全会话闭包 | useReplQueryCallbacks 已经通过 ctxRef 读取消息上下文，未重复实现 |
| 工具索引快照 | 前轮已修复行级裁剪，对照本机 CC 二进制确认 |
| 字素、行宽、Markdown、高亮缓存 | 前轮已增加容量预算及超大条目限制 |
| FileStateCache | 现有 100 项/25 MiB 默认预算，不属于完全无上限缓存 |
| 布局/WASM | 当前是 TypeScript Yoga 移植，CC 的 WASM 线性内存修复不能直接移植 |
| 字符、超链接池与过渡缓存 | 已有周期迁移/清理；样式池 ID 仍要求会话内稳定，未进行会破坏屏幕引用的强制清空 |
| 附件管线 | 已并行处理同阶段附件；阶段之间有 nested memory 依赖，不做无依据重排 |
| 流式 watchdog、文件读取缓存 | 前轮已复用定时器并限制读取缓存载荷 |

X 搜索没有获得可以用于验证本次实现细节的直接帖子，未用转述替代官方或二进制证据。此表是本次检查覆盖面，并不表示所有子系统都已完成长期压力测试。

## 验证与剩余限制

Ink、消息转换、索引、虚拟列表相关测试 164 项通过；另外运行 ReplStore 输入隔离、方向键路由和新规范化测试共 13 项通过（其中规范化测试与前组重复）；异步大小边界测试 1 项通过。运行 bun run format、bun tsc --noEmit。

尝试以原生 ConPTY 启动 bun run dev 并执行 /help，启动阶段超时（exit 124），没有取得可用于判断本次回车延迟的有效端到端结果；这也不是在真实 JetBrains Reworked 中的验证。尚未测得实际模型请求的首 token 延迟。

如需在实际会话保留阶段计时，可在 PowerShell 中启动：

```powershell
$env:ZY_CODE_PROFILE_QUERY = '1'
bun run dev
```

现有 debug 日志会记录查询阶段报告；计时有额外开销，完成诊断后可用 `Remove-Item Env:ZY_CODE_PROFILE_QUERY` 恢复普通启动。此次没有自动修改用户环境或跳过任何输入/hooks/权限处理。
